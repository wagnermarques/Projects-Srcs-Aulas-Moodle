* Introdução

Este curso será desenvolvido em conjunto com o projeto deste repositório. A proposta não é apresentar toda a teoria antes da prática, mas sim evoluir o projeto em etapas curtas, executáveis e versionadas.

1. o projeto serve como referência prática;

3. os conceitos aparecem depois da utilização prática, para reforçar o entendimento com base no que já foi visto em funcionamento.

* Etapa 1 - Estrutura inicial do projeto

** Parte prática

A primeira entrega prática deste curso deverá deixar o projeto com uma estrutura mínima semelhante a esta:

#+begin_src text
meu-projeto/
├── docker-compose.yml
├── composer.json
└── tests/
    └── google_search.php
#+end_src

O primeiro script pode ser simples, como uma automação de abertura de página e pesquisa, apenas para validar a comunicação entre PHP e Selenium antes de avançarmos para um caso mais realista como login.

Um exemplo mínimo de =docker-compose.yml= para esta etapa é:

#+begin_src yaml
services:
  selenium:
    image: selenium/standalone-chrome:latest
    container_name: selenium-chrome
    ports:
      - "4444:4444"
    shm_size: 2gb

  php:
    image: php:8.3-cli
    container_name: php-selenium
    working_dir: /app
    volumes:
      - ./:/app
    depends_on:
      - selenium
#+end_src

No projeto, a dependência principal desta etapa será:

#+begin_src bash
composer require php-webdriver/webdriver
#+end_src

Um exemplo básico de script PHP para validar a integração é:

#+begin_src php
<?php

require __DIR__ . '/../vendor/autoload.php';

use Facebook\WebDriver\Chrome\ChromeOptions;
use Facebook\WebDriver\Remote\DesiredCapabilities;
use Facebook\WebDriver\Remote\RemoteWebDriver;
use Facebook\WebDriver\WebDriverBy;

$serverUrl = 'http://selenium:4444/wd/hub';

$options = new ChromeOptions();
$options->addArguments(['--headless=new', '--no-sandbox', '--disable-dev-shm-usage']);

$capabilities = DesiredCapabilities::chrome();
$capabilities->setCapability(ChromeOptions::CAPABILITY, $options);

$driver = RemoteWebDriver::create($serverUrl, $capabilities);

$driver->get('https://www.google.com');

$input = $driver->findElement(WebDriverBy::name('q'));
$input->sendKeys('Selenium WebDriver');
$input->submit();

sleep(2);

echo "Titulo da pagina: " . $driver->getTitle() . PHP_EOL;

$driver->quit();
#+end_src

** Como executar a etapa 1

#+begin_src bash
docker compose up -d selenium
docker compose run --rm php php tests/google_search.php
#+end_src

Se for necessário executar mais de um comando dentro do contentor PHP:

#+begin_src bash

#+end_src

** Conceitos apresentados após a prática

Depois de montar e executar a etapa 1, entram os conceitos que explicam o que acabou de acontecer:

1. **Selenium**: servidor que recebe comandos e controla o navegador remotamente;
2. **Docker Compose**: forma de subir e relacionar os serviços do ambiente;
3. **contentor PHP**: ambiente isolado onde os scripts de automação serão executados;
4. **WebDriver**: biblioteca e protocolo usados para comunicar com o navegador;
5. **modo headless**: execução do Chrome sem interface gráfica, útil para automação e CI;
6. **estrutura mínima do projeto**: separação entre configuração do ambiente, dependências e scripts de teste.

Ao final desta etapa, o aluno deve conseguir:

* Etapa 2 - Primeiro teste de login mais básico possível

** Parte prática

Com a infraestrutura validada, a etapa seguinte será trocar o exemplo genérico por um teste de login simples. A implementação deverá priorizar o menor fluxo possível:

1. abrir a página de login da aplicação alvo;
2. localizar os campos de autenticação com seletores estáveis;
3. preencher credenciais de teste;
4. submeter o formulário;
5. verificar um único sinal de sucesso, como URL esperada, título, mensagem ou elemento da área autenticada.

Esta etapa deve continuar simples de executar e fácil de ler. Se surgir a necessidade de refatoração, ela deve ficar para etapas futuras, depois que o fluxo básico estiver comprovado.

** Conceitos apresentados após a prática

Depois que o primeiro login automatizado estiver a funcionar, os conceitos associados devem ser explicados:

1. **seletores estáveis**: preferência por =id=, =name= ou atributos próprios de teste;
2. **esperas**: evitar depender apenas de =sleep()= quando já houver elementos que possam ser aguardados explicitamente;
3. **validação mínima**: confirmar apenas o essencial para provar que o login funcionou;
4. **dados de teste**: manter credenciais e ambiente de teste controlados;
5. **evolução incremental**: primeiro fazer funcionar, depois melhorar organização, reuso e cobertura.

** Resultado esperado da etapa 2

Ao final desta etapa, o projeto deverá demonstrar um login automatizado simples e o tutorial deverá explicar esse fluxo com base no que foi feito, e não como teoria isolada.
