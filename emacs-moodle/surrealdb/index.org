* Página 1: O que é o SurrealDB?

**SurrealDB** é um banco de dados **multimodelo**: em um único motor com garantias **ACID**, ele suporta documentos, grafos, vetores e séries temporais — dados que, tradicionalmente, exigiriam bancos separados (um documental, um de grafos, um vetorial...).

A proposta oficial do projeto é ser *"graphs, vectors, documents, and relational data in one engine"*, posicionando-se também como uma **camada de dados unificada para aplicações de IA**, servindo tanto como banco de dados de propósito geral quanto como camada de memória para agentes.

* Página 2: Por que um Banco de Dados Multimodelo?

Em uma arquitetura tradicional, é comum combinar várias ferramentas especializadas: um banco relacional para dados transacionais, um banco documental para conteúdo flexível, um banco de grafos para relacionamentos e um banco vetorial para busca por similaridade (embeddings de IA). Cada peça extra soma **complexidade operacional**: mais serviços para manter, sincronizar e garantir consistência entre si.

O SurrealDB unifica esses modelos em um único motor:

- **Documentos:** registros flexíveis, sem esquema rígido obrigatório.
- **Grafos:** relacionamentos modelados como arestas de primeira classe, com travessia nativa na linguagem de consulta.
- **Vetores:** suporte a busca por similaridade, útil para RAG (*Retrieval-Augmented Generation*) e outras aplicações de IA.
- **Séries temporais e dados relacionais:** consultas estruturadas tradicionais, com transações ACID.

* Página 3: Instalando e Iniciando um Servidor Local

**Linux:**
#+BEGIN_SRC bash
curl -sSf https://install.surrealdb.com | sh
#+END_SRC

**macOS (via Homebrew):**
#+BEGIN_SRC bash
brew install surrealdb/tap/surreal
#+END_SRC

**Verificando a instalação:**
#+BEGIN_SRC bash
surreal version
#+END_SRC

**Iniciando uma instância local em memória** (ideal para testes e aprendizado, sem persistência em disco):
#+BEGIN_SRC bash
surreal start --user root --pass root memory
#+END_SRC

* Página 4: SurrealQL — A Linguagem de Consulta

O SurrealDB usa **SurrealQL**, uma linguagem de sintaxe próxima ao SQL, porém estendida para lidar naturalmente com objetos aninhados e travessia de grafos.

**Criando e consultando registros:**
#+BEGIN_SRC surql
-- Cria um registro na tabela "person"
CREATE person:tom SET name = "Tom", age = 28;

-- Consulta simples, com filtro
SELECT name, age
FROM person
WHERE age >= 18;
#+END_SRC

**Consultando campos aninhados e relações, em uma única consulta:**
#+BEGIN_SRC surql
SELECT name,
       metadata.{
          date_registered,
          last_login
       },
       ->wrote->post AS posts
FROM user
WHERE age >= 18;
#+END_SRC

Note como `->wrote->post` já realiza, dentro do próprio `SELECT`, uma travessia de grafo — sem a necessidade de `JOIN`s explícitos como em um banco relacional tradicional.

* Página 5: Modelagem de Grafos com =RELATE=

Relacionamentos no SurrealDB são registros de primeira classe, criados com a instrução =RELATE=. Isso evita duplicar a informação de relacionamento dentro das tabelas envolvidas.

#+BEGIN_SRC surql
CREATE person:aristotle, article:on_sleep_and_sleeplessness;

RELATE person:aristotle->wrote->article:on_sleep_and_sleeplessness;
#+END_SRC

Esse comando gera automaticamente um registro na tabela de aresta =wrote=, com campos =in= (origem) e =out= (destino):

#+BEGIN_SRC surql
[
  {
    id: wrote:bpbrj5kd7smu3ahlf55r,
    in: person:aristotle,
    out: article:on_sleep_and_sleeplessness
  }
]
#+END_SRC

Como a documentação oficial destaca: nenhuma informação de relacionamento fica armazenada nas tabelas =person= ou =article= — ela vive na aresta =wrote=, permitindo travessias eficientes sem necessidade de =JOIN=.

* Página 6: SurrealDB em Aplicações de IA

Além de uso geral, o SurrealDB é posicionado como uma **camada de memória para agentes de IA**, combinando busca vetorial (embeddings), grafos de conhecimento e documentos na mesma base — o que é particularmente útil em pipelines de **RAG** (*Retrieval-Augmented Generation*).

    <li>A Tencent executa mais de <strong>10.000 consultas por segundo</strong> sobre arestas de grafo.</li>
    <li>A PolyAI relata latência de aproximadamente <strong>30ms</strong> em operações de RAG.</li>

A ideia central é reduzir a fragmentação típica de pipelines de IA — onde embeddings, metadados e relacionamentos ficam espalhados em bancos vetoriais, documentais e de grafos separados — unificando tudo em um único motor consultável via SurrealQL.
