** [MCQ] Time Complexity of Binary Search
:PROPERTIES:
:TYPE: multichoice
:SINGLE: true
:SHUFFLE: true
:DEFAULTGRADE: 1.0
:FEEDBACK: Binary search repeatedly divides the search interval in half, yielding logarithmic performance.
:END:
What is the worst-case time complexity of running a *Binary Search* algorithm on a sorted array of \(n\) elements?

- [X] \(\mathcal{O}(\log n)\) :: Correct! Halving the search space at each step gives logarithmic time.
- [ ] \(\mathcal{O}(n)\) :: Incorrect. \(\mathcal{O}(n)\) is the complexity of Linear Search.
- [ ] \(\mathcal{O}(n \log n)\) :: Incorrect. \(\mathcal{O}(n \log n)\) is the typical complexity of efficient sorting algorithms like Merge Sort.
- [ ] \(\mathcal{O}(1)\) :: Incorrect. Constant time is achieved by direct array index lookup or hash tables.

** [TF] P vs NP Problem Definition
:PROPERTIES:
:TYPE: truefalse
:DEFAULTGRADE: 1.0

The class **NP** consists of all decision problems that can be *verified* in polynomial time by a deterministic Turing Machine.

- [X] True :: Correct! NP stands for Nondeterministic Polynomial time, meaning solutions can be verified efficiently in polynomial time.
